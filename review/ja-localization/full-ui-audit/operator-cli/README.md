# Operator CLI findings and runtime evidence

Product source: `fe0cf0878e35236ec9716f5d3ee237fff11c3480`; local build identity in the captured output remains `0.2.3-dev.20261026-085553+gb703b9ea`. Product runtime code did not change between those revisions; the later commit adds the startup audit.

`surfaces.csv` records noninteractive dispatcher routes and each parser `UsageError` construction site independently of the catalog mapping. It is source evidence for state families, not proof that every input permutation was invoked. `existing_test` is a related test pointer, not a per-row execution result.

`observations.json` contains 40 observations: English and Japanese for 20 safe scenarios. These use actual compiled CLI startup in isolated temporary homes, stripped ambient credentials and a denying fetch hook. Expected exit statuses are asserted. Only read-only commands, invalid inputs, migration confirmation refusal and absent-rollback-receipt paths are invoked; no real account, installation, model request or user configuration is modified. Machine paths are replaced with `<temporary-root>`, `<checkout-root>`, `<node-executable>`, `<node-directory>`, `<system-temp>` or `<user-home>`.

Observed Japanese framing is present in help, doctor, catalog status/missing-file errors, keybinding plans, profile plans, migration preview/refusal/absent rollback, updater status, parser errors and pinned-runtime update refusal. This is not whole-command Japanese approval:

- Invalid catalog records produce `モデルカタログが無効です: $.format: must equal jouzu.model-catalog`. The wrapper is Japanese; the schema diagnostic originates in the catalog validator. Classify source-diagnostic preservation separately before requesting translation. Missing-file diagnostics use a message descriptor and do render in Japanese.
- Profile plan rows retain machine action/reason values such as `create`, `state-update`, `missing`, and `no previous profile state`. A localized heading does not prove every displayed value is translated. These need display-policy review without changing stored identifiers.
- Updater status retains machine result vocabulary such as `never`. Source checkout applicability, policy and missing-value explanations are Japanese in the observed scenario; actual download/install/restart outcomes were not exercised.
- Doctor/catalog `--json` output is machine-readable and includes machine IDs, source diagnostics and recorded metadata. English machine output is not automatically a missing human-interface translation.
- Catalog-unavailable recovery deliberately has an English fallback independent of a working Japanese bundle. That boundary must remain explicit rather than silently accepted as Japanese rendering.
- The separate Python reservation entry point has English-only argparse help/banner text and no interface-locale option. It is not the distributable Node CLI and must not be confused with Japanese support in `jz`.

`component-observations.json` adds controlled constructor/render reproductions, generated by `observe-components.mjs`. Runtime diagnostics constructed with the production arguments use English; explicitly supplying the Japanese catalog produces Japanese. The subagent widget still renders `Subagents · 1 active · 0 queued · 0 finished` and `Details: /subagents · Hide: /subagents hide` even with an explicit Japanese catalog, at widths 48 and 100. No real subagent was launched. These are component reproductions plus source-wiring evidence, not an observed `/about` or native widget session.

The observation corpus does not include actual network refresh, accepting a real quarantine, profile/keybinding writes, migration confirmation/apply/rollback writes, updater check/apply/policy mutation, damaged installation, or native-terminal interaction. Related deterministic tests may exercise injected implementations; they are not real account/update/install evidence. See the full audit's runtime blockers.
