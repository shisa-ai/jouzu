# Jouzu v0.1.14

This release improves background-work coordination, Shisa account setup, runtime diagnostics, and bug reporting. It also updates the embedded Pi runtime and makes prompt-cache warming opt-in.

## Background work and recovery

Subagent launches and scheduled prompts return receipts that `agent_wait` can use without polling. Subagent waits track one exact run. Schedule waits track the first trigger of a newly created schedule, not completion of its work. Tasks can wait on background jobs started by their parent turn without taking ownership of those jobs.

Completed execution takes precedence over a health check when a job finishes during wait registration. Unreadable producer state keeps automatic work held while allowing `/flow` inspection and recovery. `/about` remains available during a hold without releasing it.

Subagent session and workspace locks last for the lifetime of the owning process. Exiting or killing that process releases the locks; suspending it keeps them held. Storage failures are reported rather than leaving work queued indefinitely. **Close other Jouzu processes before upgrading:** versions before v0.1.14 do not share these process-held locks.

Empty request-history records are bounded during continuous tool runs. Cancelled tool results remain intact when cancellation occurred before content scanning. Empty sessions are omitted from the resume list without preventing explicit session recovery.

## Work summaries and runtime identity

Goals and loops leave a summary card when they finish, stop, or pause. Cards show the outcome, objective, elapsed time, activity counters, and resume command where applicable. Measured runs also show the metric and acceptance result. Background completion receipts include finish times and durations.

`/about` shows the running and installed Jouzu builds, Pi version, and startup time. `/session` includes a compact runtime line. If the installed build differs from the running build, restart Jouzu to load it.

## Shisa account setup

First launch explains access to open coding models such as Qwen and GLM, the $10 signup credit offer, and the additional $25 offer for attaching a credit card. Connecting is optional; `/login shisa` remains available later.

Settings / Catalogs includes a Shisa AI account row with in-panel browser approval and confirmed sign-out. A saved sign-in shows its organization; an environment key identifies `SHISA_API_KEY` without borrowing a saved account's identity. The row scrolls with the catalog pane so expanded catalog offerings can use the space.

Signing in refreshes authenticated catalogs and model availability in the same session. If credentials were saved but server confirmation failed or was interrupted, Settings retains the warning and asks you to sign in again. Signup offers are not shown as an account balance.

## Bug reporting

`/bug` prepares an editable issue draft with the reported problem, reproduction details, and minimal runtime information. It always provides the [Jouzu issue form](https://github.com/shisa-ai/jouzu/issues/new). When an authenticated GitHub CLI account is verified, it also offers to submit as that user after explicit confirmation. Keeping the draft is the default.

Reports collect no transcript or attachments automatically, and drafting makes no model request. Review the title and body before posting: GitHub issues are public. An uncertain submission result keeps the draft and asks you to check existing issues before retrying. See [Report a Jouzu bug](https://github.com/shisa-ai/jouzu/blob/v0.1.14/docs/bug-reporting.md).

## Runtime and cache settings

The embedded Pi runtime is updated from 0.85.1 to 0.86.1. System instructions survive cancelled user input, compacted summaries are checked by message role, and native clipboard helpers ship with the runtime.

Prompt-cache warming defaults to `off`. Explicit `streaming` and `idle` modes remain available in `/settings`; ordinary provider-side prompt caching is unaffected. Refresh requests have separate admission checks, child refresh usage is included in parent totals, and new or resumed children inherit the global warming setting. See [Prompt-cache warming](https://github.com/shisa-ai/jouzu/blob/v0.1.14/docs/cache-warming.md) for provider-dependent behavior and limitations.

Model-picker history is limited to 512 projects and 16 MiB while preserving explicit defaults, favorites, and reasoning preferences. Content scanning uses the embedded TextGuard scanner; the optional Python comparison-scanner flags from v0.1.13 are removed.

## Installation and testing limits

Update with `npm install -g jouzu@0.1.14` or Jouzu's updater. Windows setup requirements remain documented in [Windows setup](https://github.com/shisa-ai/jouzu/blob/v0.1.14/docs/windows.md).

Account-flow tests use isolated loopback services to verify credential persistence, catalog activation, and model authentication in one session; they do not establish live signup or inference behavior. Cache refresh lifecycle tests do not establish provider cache retention or savings. The Windows installer preview remains unsigned, and clean Windows 10/11 installer acceptance is separate from CLI qualification.
