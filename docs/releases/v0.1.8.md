# Jouzu v0.1.8

Draft — not yet released.

## TextGuard scanning included

Jouzu scans skills and web results locally by default with bundled TextGuard. No separate Python installation is required. Content with blocking findings or an incomplete check stays out of model context. `/textguard` shows withheld items and their available review actions.

Approval applies only to that content in the current session. Child agents have separate checks and cannot approve withheld content. To check ordinary file reads too, start Jouzu with `--jouzu-textguard-files`.

Scanning does not guarantee that content is safe and does not restrict shell commands. See [TextGuard scanning](https://github.com/shisa-ai/jouzu/blob/main/docs/textguard.md) for coverage and limits.

## Voice input

Use `/voice` to start microphone dictation and `/voice stop` to insert the transcript into the prompt. The preview distinguishes live text from finalized chunks. Missing speech becomes `[garbled]`, so you can correct it before sending. `/voice cancel` discards the recording. Nothing is sent to the coding model automatically.

Voice requires `SHISA_API_KEY` with realtime speech access. Audio is sent to Shisa; Jouzu writes no recording files. Capture uses the machine running Jouzu, including over SSH. Live microphone behavior and transcription quality still need testing. See [Voice input](https://github.com/shisa-ai/jouzu/blob/main/docs/voice.md).

## Fewer completion interruptions

Background tasks and child agents wait until active work and queued messages finish before delivering unread completion summaries. Results the agent has already read do not start another completion response. Batches that need no reply can end with a visible **No reply needed** acknowledgement.

Child results also have compact, color-coded summaries with model, assignment, status, and outcome. Expanded output shows usage and review details. A completed run is not an approval of the work.

## Model and workflow improvements

- Reasoning overrides are saved per model. Without a user override, Jouzu uses the catalog default, then the configured global default. Explicit startup settings and resumed sessions keep their choices.
- Child agents can start in a selected workspace and read sibling repositories through their enabled tools. Review identity checks cover the selected checkout; assignments involving multiple repositories still need separate coverage evidence.
- Default child limits increase to 500 turns and two hours. Existing saved definitions and active runs are unchanged.
- Palette tabs and Workflow/Settings rows have aligned columns, selection highlights, and clearer status colors. Workflow preserves line breaks in child output.
- Plain-HTTP catalog sources are accepted with an unencrypted-token warning.

## Build from source

`npm run dev:setup` installs locked dependencies, checks and builds the local copy, and tests startup without changing global command links. Use `npm run dev:link` if you want `jz` and `jouzu` to point to that checkout. Automatic rebuild hooks are opt-in.

See the [source-build instructions](https://github.com/shisa-ai/jouzu#development) for prerequisites and commands.
