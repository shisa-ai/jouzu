# Jouzu v0.1.5

Jouzu v0.1.5 adds a built-in Shisa model catalog, consolidates goals and measured loops into one workflow package, and lets the agent request context compaction.

## Built-in Shisa catalog

When `SHISA_API_KEY` holds a bearer token, the built-in `shisa-api` source reads the account's model catalog from `https://api.shisa.ai/v1/jouzu/model-catalog` without any source configuration. Interactive startup refreshes each enabled source whose credential is available, in the background, while cached catalogs keep serving. Without the key and without a configured source, Jouzu makes no catalog request. The token is sent only as the source's authorization header, is never written to configuration, cache, or diagnostics, and authenticated refresh never follows redirects.

Settings / Catalogs (`/catalogs`) manages named sources: add, edit, enable/disable, refresh, and remove, with per-source ETag validation, account-partitioned cache, mass-change quarantine, and last-known-good retention. The built-in source can be disabled there without storing a credential; a manual registration with the same endpoint and credential reference keeps its label, enabled state, and cache. `jouzu catalog status|refresh [source-id]` and `jouzu catalog accept REVISION --digest SHA256 --source SOURCE_ID` provide CLI parity. `JOUZU_MODEL_CATALOG_URL` and `JOUZU_MODEL_CATALOG_TOKEN` remain a single-source shorthand when `catalogs.json` is absent.

The catalog supplies metadata only. It does not configure provider authentication, write `models.json`, or prove that a model call can run.

## One workflow package

`pi-multiloop` 0.4.0 provides `/goal`, `get_goal`, and `update_goal` alongside `/multiloop`; `@lhl/pi-goal` is no longer part of the product, and the bundle falls from ten release-owned extensions and two package skills to nine and one. `/goal <objective>` starts immediately, deriving its own lane, mode, and scope instead of asking setup questions. A goal writes the same `.multiloop/` state as a measured run, so it is listable and resumable with its history; goals recorded by v0.1.4 remain readable. `/multiloop` reaches launch on one approval when its repository scan proposes a complete configuration.

Upgrade note: a separately installed `@lhl/pi-goal` copy now conflicts with the release-owned goal tools. The load error identifies the copy and points to `jz config` to disable or remove it.

Each run tracks elapsed time, turns, tool calls, and token totals, reported in the footer, `/goal`, `/multiloop status`, and the end-of-run summary. These counters no longer appear in the model's context, where a running total read as a context-window gauge and could cut work short.

## Model-requested compaction

The agent can ask for context compaction with `compact_context`. The request runs after the current turn ends, uses the bundled pi-vcc compactor, and leaves earlier messages searchable through `vcc_recall`. Threshold and overflow compaction remain automatic.

## Models and Palette changes

- The Palette shows Models and Settings as top-level sections; `Tab` and `Shift+Tab` move between them.
- In Models, `←` and `→` change the Recent, Favorite, or All view; typing or `/` focuses search; a non-empty query ranks the full model inventory from every view; `Esc` returns to browsing with the query intact before another `Esc` closes the Palette.
- `Enter` selects the model and stores it as the user-local project default. New sessions resolve an explicit `--model`, then a resumed session's recorded model, then the project default, then the last dispatched model with its thinking level.
- Favorites toggle with `Ctrl+F`, replacing the `Shift+Enter` and `Ctrl+Shift+S` accelerators, which some terminals cannot deliver. Inside the Models search field `Ctrl+F` takes precedence over cursor-right, where `→` remains available. Rebind through `jouzu.model.toggleFavorite` in `keybindings.json`.
- A model switch is blocked when the estimated active context plus a 4,096-token safety margin exceeds the target's context window; a `context-small` target offers confirmed compaction of the active transcript before switching.

## Platform

Smart Fetch and Camoufox are optional integrations. If either cannot load, Jouzu starts without its tools and displays a warning; `jz doctor` lists the disabled tools, reports the underlying error, and exits with status 1. The selected native bindings support glibc 2.28 or newer. On older enterprise Linux distributions, Camoufox's Firefox runtime needs the system GTK/X11/audio libraries, and `JOUZU_CAMOUFOX_LIBRARY_PATH` can point the browser child at a compatible NSS.

The bundled extension set is qualified on Linux, macOS, and Windows with Node 22 and 24.

## Requirements

Jouzu v0.1.5 requires Node.js 22.19 or newer, npm, Git, Bash, and a separately authenticated Pi-supported model provider. Windows requires Git Bash and a UTF-8-capable terminal.

Install from npm:

```bash
npm install --global jouzu@0.1.5
jz doctor
jz
```

Eligible global npm installations can update with:

```bash
jz self-update apply
```

## Limitations

The included extensions run with the user's permissions. Network tools contact the requested sites, and Camoufox may download its browser binary on first browser use. Arbitrary additional Pi packages have their own provenance and platform support.

The optional catalogs supply metadata; they do not provide model access, authentication, routing, cost, privacy, retention, region, or certification guarantees.

npm is the only functional v0.1 channel. PyPI `jouzu==0.0.1` remains a non-functional reservation.
