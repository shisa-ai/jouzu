# Jouzu v0.1.15

This release gives subagents their own context, resources, and visibility, makes long sessions durable, and upgrades the embedded Pi runtime to 0.87.1.

## Subagent children

A subagent launch chooses its context: `fresh` starts independent, `fork` shares the parent conversation as references, and `splice` shares selected entries. A child can read bounded parent context without inheriting it. Snapshots are retained across resume, and review roles default to independent context.

Children load bundled extensions, discovered skills, active profile guidance, and TextGuard. Their work joins task, background, scheduled, and compaction continuations, with cancellation and total turn limits unchanged.

The dashboard above the editor shows child activity, hides and shows on demand, and routes to Runs. Run selection survives dashboard updates.

Parent and child session traces are written as bounded, filterable JSONL with resumable byte cursors. Tracing is read-only: it does not change completion receipts or saved sessions.

Scheduling stays under parent ownership. The scheduler is excluded from every child role, and a saved child schedule is disabled before resume restores automation. Invalid child schedule state is preserved under a quarantine name with a persistent warning instead of blocking resume.

See [Agents and runs](https://github.com/shisa-ai/jouzu/blob/v0.1.15/docs/subagents.md).

## Long sessions

Background execution state and retained results move into a versioned canonical sidecar with bounded progress persistence, migration markers, fail-closed recovery, and session-transition handling. The whole-transcript history capacity lockout is removed, and long sessions use record-bounded streaming and writer-aware indexed verification.

## Flow control and continuations

A command's own send counts as the user's instruction, so `/goal resume` and similar sends are admitted where typed input is instead of being held with no visible effect. A refused user submission and a reopened session's recovery hold are reported once per message and reason, so a hold is never visible only to someone who runs `/flow`.

An undispatched continuation stays retained across reattachment and is issued again at the next release boundary; the superseded record is retired so it is not issued at every later open. Each inherited continuation is issued on its own during replay, so a record that cannot be sent or retired no longer stops the records behind it.

A multiloop lane whose continuation was never submitted is driven again when its flow gate clears, instead of waiting for an `agent_end` that never fires on an idle session. A bare `/multiloop resume` selects the attached run, or the only active or paused run, instead of handing the choice to the agent.

## Tool calls on strict providers

Some providers require every declared property, which leaves a model no way to omit an optional field. Optional `agent_wait` fields now read the placeholders those providers force — explicit `null`, an empty string, and the documented `none` sentinel for `replaceToken` — as the omission they stand for. Required fields, unknown-field rejection, and placeholder-token refusal are unchanged.

A redeclare refusal names the live token to copy, so a caller whose context no longer holds the earlier receipt can comply. An inapplicable `checkAfter` is dropped rather than refused, and a token belonging to another work is distinguished from one that names no live wait. A rejection survives history pruning.

A declined optional argument no longer reaches a tool as a supplied value, so an empty-string placeholder cannot act as a chosen role, owner, or dedupe key.

## Runtime and skills

The embedded Pi runtime moves from 0.86.1 to 0.87.1. Session projections, queue admission, and source recovery keep their behavior across Pi's new provider-context model; the review and its evidence are in [Pi update review](https://github.com/shisa-ai/jouzu/blob/v0.1.15/docs/PI-UPDATES.md).

Core installs four optional skills, adding `jouzu-anti-slop` beside `jouzu-clear-writing`. It is a filler-removal checklist for existing prose that keeps facts, qualifiers, and exact technical content.

The output safety reserve scales to the larger of 4096 tokens or five percent of estimated input, preserving caller caps and overflow recovery.

## Installation and testing limits

Update with `npm install -g jouzu@0.1.15` or Jouzu's updater. Restart running sessions to pick up the changed wait schema and argument normalization.

Subagent, dashboard, and trace coverage uses assembled sessions and fixtures. It does not establish live-model delegation quality or trace usefulness on a real workload. Long-session storage tests cover migration, injected faults, and a bounded large-session corpus, not every filesystem. Wait-tool compatibility tests cover the all-required argument shape and nullable forms; a provider that transforms the registered schema outside the session can present a shape these tests do not reproduce.

Release qualification covers Linux and macOS on the released commit. The Windows installer preview remains unsigned, and clean Windows 10/11 installer acceptance is separate from CLI qualification.
