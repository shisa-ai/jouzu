# Jouzu v0.1.16

This release fixes opening a session after upgrading from v0.1.15.

## Flow registry recovery

v0.1.15 shortened the identity digest used as a path component, to keep a child agent's nested flow lock inside the path length SQLite can open on Windows. That digest is the directory key for flow storage, so the change also moved each session's flow registry and branch storage. The transcript kept its own markers, which then named a registry the code no longer looked for, and opening the session failed:

```text
Jouzu failed: Active Pi branch differs from its flow registry.
```

Two changes make an upgrade safe:

- Flow storage written under the previous digest is adopted when the shortened key holds nothing, so an upgrading session keeps its registry and branch history.
- A registry that still cannot be reconciled with the transcript is rebuilt from the transcript's verified marker instead of blocking the load. The transcript is the durable record and the registry is derived from it. The dropped state is saved beside the live one and reported in the session, so nothing is discarded silently.

A session that already failed to open needs no manual repair. The registry its failed attempt created is the case the rebuild handles.

## Installation and testing limits

Update with `npm install -g jouzu@0.1.16` or Jouzu's updater.

Flow recovery coverage uses fixture registries and transcripts. It does not establish behavior for every registry shape an earlier version could have written. The subagent state root uses the same digest without an adoption path, so upgrading can orphan a subagent run's stored state; that never blocks opening a session.

The Windows installer preview remains unsigned, and clean Windows 10/11 installer acceptance is separate from CLI qualification.
