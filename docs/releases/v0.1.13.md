# Jouzu v0.1.13

This release adds session-scoped flow control, durable conversation-branch reactivation, bounded flow retention, and clearer Windows installation failures.

## Flow control off and on

`/flow off` takes flow control out of the circuit for the session: what you send runs as an ordinary turn, and jobs, tasks, and loops deliver their own notifications instead of flow control composing them. `/flow on` puts it back. Both keep the session, its records, and every running job. Producer tools and their own delivery paths keep working while it is off, and `/flow runtime` still reports the running and installed versions.

While flow control is off, every flow tool refuses with the same message and `/flow` reports the state. `/flow reset` turns it off and on in order.

## Conversation branches

Returning to where you last left a recent conversation branch resumes its unfinished work, including a wait on a background job, and a retained late result stays readable on that branch. Restart rebinds the session to the branch that owns the newest transcript entry. A rewind inside the active branch still starts a new branch with nothing inherited, and an interrupted transition recovers by rebinding to the branch that owns the leaf instead of holding the session.

Branch records are bounded by a byte budget rather than a record count, so a session with many small branches stays inside the same limit. An automated turn that no producer owns now receives host work, so its tools run instead of being refused.

## Flow retention and indexing

Completed, cancelled, and archived flow work retires into indexed history: submissions, native requests and their retry chains, cancellations, waits, results, and the identities that read them. Retained evidence stays readable after retirement, and routine reads query exact records instead of scanning bounded windows, so a long session no longer accumulates unbounded active records or exhausts a lifetime quota with repeated completed work.

An explicitly reset native request that never reached an outcome is retired, a completed retry chain retires as one group, and cancellation checks stay in force after a request is retired. Producer rounds survive nonprefix retirement, and retirement authorization is rechecked before the ledger commits.

## Browser tools

The Camoufox browser stops after five minutes without a `tff-fetch_url` or `tff-search_web` call, and the next call relaunches it. Set `JOUZU_CAMOUFOX_IDLE_STOP_MS` to a whole number of milliseconds from 1000 to 2147483647 to change the delay, or `0` to keep the browser loaded until the session ends. An invalid value keeps the browser tools from loading until it is fixed. Stopping releases the browser process; runtime modules already loaded in the session stay in memory.

## Installation

Update an npm installation with `npm install -g jouzu`, or use Jouzu's automatic updater. A failed Windows installation now names the stage that failed, the launcher error, and the automatic setup log path, and each activation check allows 90 seconds instead of 30. This release also provides an unsigned Windows x64 installer preview. See [Windows installer preview](https://github.com/shisa-ai/jouzu/blob/v0.1.13/packaging/windows/README.md) for installation, rollback, and the `/LOG` flag for diagnosing activation failures.

## Testing limits

Flow retention and indexing changes are covered by component tests with controlled fixtures; long-session behavior under live provider traffic is not measured. Conversation-branch recovery is verified with controlled transcripts, not live-provider recovery. Native Windows installer acceptance covers Windows Server 2025 x64; clean Windows 10/11 testing remains pending, and the installer is unsigned.
